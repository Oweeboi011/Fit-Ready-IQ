# IDP Audit — Fit-Ready-IQ (2026-07-16)

Audit of the Internal Developer Platform across three layers: solution tooling, path definitions, and agent infrastructure. Companion fixes applied in the same change are noted inline; open gaps are listed at the end for separate prioritization.

## Layer 1 — Solution Tooling

### Dev Control
- **Pre-commit**: Husky (`.husky/`, driven by `src/frontend/package.json`'s `prepare` script) runs `lint-staged` (ESLint --fix + Prettier) on staged TS/TSX files; `commit-msg` enforces Conventional Commits via commitlint.
- **CODEOWNERS** (`.github/CODEOWNERS`): single owner (`@oweeboipenaranda`) for everything, with explicit call-outs for `src/frontend/src/app/api/` (secrets/auth surface), Firestore rules/indexes, and CI/CD config — sensitive-surface review routing rather than team-based ownership.
- **PR template** (`.github/pull_request_template.md`): requires a summary, change-type checkbox, and a test-plan checklist (type-check, lint, unit tests, manual smoke test).
- **Branch protection**: documented consistently in `.claude/CLAUDE.md` and `docs/wiki/DEPLOYMENT.md` (direct pushes to `main` blocked, 4 required status checks, merge queue, 1 approving review, stale-review dismissal) — but this is a GitHub Settings toggle, not codified in any repo file. **Cannot be verified from source alone.** (Open gap #1.)

### Integration & Delivery
- `ci.yml`: PR/push to `main`. Frontend job — lint, type-check, unit tests, build. Backend job — ruff, mypy, pytest (backend isn't deployed yet, but CI still gates it).
- `e2e.yml`: PR to `main`, Playwright/Chromium against real secrets.
- `mutation.yml`: PR-only, scoped to `src/frontend/src/lib/**`, Stryker mutation tests (70%/80% break/high thresholds).
- `agent-review.yml`: advisory-only Claude Haiku PR comment bot, 10 KB diff cap, 1024 max tokens, skippable via `[skip review]`. Cannot block merges.
- **Fixed**: `deploy-pages.yml` has been removed. It built a static GitHub Pages export on every push to `main`, undocumented anywhere, and conflicting with the README's canonical Vercel deploy story — a static export can't serve the app's `/api/*` routes (chat, weather, Strava, admin), so it was shipping a non-functional build.

### Resources
- `docker-compose.yml`: three services for local dev — Firebase emulators (Firestore/Auth/Storage + UI, healthchecked), backend (FastAPI, hot-reload), frontend (Next.js dev server). No production infrastructure is defined in-repo (expected — production is Vercel-managed, outside this repo's IaC).

### Quality and Security
- `security.yml`: npm audit (`--audit-level=high`), pip-audit (osv), gitleaks secret scan (default ruleset, no `.gitleaks.toml`), and CodeQL — runs on PR, push to `main`, and weekly (Monday 06:00 UTC).
- `dependabot.yml`: weekly updates for npm, pip, and GitHub Actions, capped at 5 open PRs each.
- **Fixed**: CodeQL previously only scanned `javascript-typescript`; it now runs a matrix across `javascript-typescript` and `python`, since the FastAPI backend is first-class code with auth/API-key handling logic that was previously unscanned.
- **Fixed**: `src/src/backend/pyproject.toml` listed `black`, `isort`, `pylint`, `flake8` as dev dependencies with their own config blocks, but `ci.yml` only ever runs `ruff` and `mypy`. Removed the unused tools and config blocks — they were dead weight that misrepresented what's actually enforced.

### Observability
- Frontend `/api/health` checks env-var presence/validity (not live connectivity) for all external integrations.
- Backend `/health` + `structlog` (JSON, ISO timestamps) exist.
- **Fixed**: `sentry-sdk` was listed as a backend dependency but never initialized anywhere. Added a `sentry_dsn` setting (`src/backend/src/config/settings.py`, defaults to `None`) and a guarded `sentry_sdk.init(...)` call in `src/backend/src/main.py` that only fires when a DSN is configured — local/dev runs are unaffected.
- No uptime/alerting/synthetic monitoring exists anywhere — `/api/health` exists but nothing polls it automatically. (Open gap #4.)

## Layer 2 — Path Definitions

- **Deterministic (Validate → Promote → Deploy)**: Validate is fully implemented (lint/type-check/test/build/security/mutation gates). Promote relies on the unverifiable-from-repo branch protection setting above. Deploy previously had two conflicting paths (Vercel + GitHub Pages); now single-path via Vercel only.
- **Probabilistic (Agent-Driven)**: the only agent-driven step is `agent-review.yml`, which posts an advisory comment and has no authority to dispatch work, merge, or remediate. There is no "Dispatch Work," "Retrieve Context," or "Remediate Change" automation in this repo today — those stages are entirely human-driven.
- **Hybrid (Agent + Gate)**: "Promote Changes" is nominally hybrid (bot comment feeds into a human-gated merge) but the bot has no blocking power, so in practice it's just an input to a human decision. "Observe System" has no implementation at all — no automated observation loop exists to feed back into the pipeline. This is the largest Layer 2 gap. (Open gap #4.)

## Layer 3 — Agent Infrastructure

### Harnessing
- **Context**: `.claude/CLAUDE.md` is the primary, hand-maintained memory file (architecture, commands, data model, credential split). `.github/instructions/*.md` provide Copilot-style scoped instructions via `applyTo` globs. No RAG/embedding-based retrieval exists anywhere — all context is static and manually kept in sync. `.claude/skills/tdd/SKILL.md` references a `CONTEXT.md` file that does not exist in the repo (open gap, not fixed this pass — low risk, but worth creating or removing the reference).
- **Fixed**: `.github/instructions/copilot-instructions.md` and `typescript-react.instructions.md` contained template leftovers from an unrelated project — a full Avanade brand-color/typography spec, references to PostgreSQL/Azure Container Apps/Bicep (none of which this repo uses), "Biome" instead of the actual ESLint/Prettier setup, a Jest example where the repo uses Vitest exclusively, a coverage table that didn't match `vitest.config.ts`'s actual thresholds, and a Clean Architecture layer table claiming `src/application/` and `src/interface/` directories that don't exist in `src/backend/src/` (only `domain/`, `infrastructure/`, `config/` do). All corrected to match the real repo state. `copilot-instructions.md` still carries a fair amount of generic boilerplate beyond these factual corrections (open gap #5, lower priority — worth a full rewrite pass against the actual codebase separately).
- **Capability**: `.github/agents/dev-agent.agent.md` grants broad tool access (terminal exec, file edit/create, browser automation, PR tools, subagent spawning) scoped only by prose ("Fit-Ready-IQ files ... only") — no technical enforcement. (Open gap #3.)
- **Execution**: `agent-review.yml` is well-scoped — `contents: read`, `pull-requests: write` only, cannot modify code. `dev-agent` runs in the invoking developer's own session with no isolation/sandboxing.
- **Evaluation**: no rubric, scoring, or eval harness exists anywhere for agent-generated output — neither the PR review comments nor any `dev-agent`-authored changes are measured against a standard. (Open gap #2.)

### Governance
- **Identity**: no distinct machine identity or scoped bot account for agents. `agent-review.yml` acts under the default `GITHUB_TOKEN` Actions identity; `dev-agent` acts as the developer.
- **Security**: secrets (`ANTHROPIC_API_KEY`, `GITHUB_TOKEN`) are handled correctly via GitHub Actions secrets, never exposed to agent tool-call surfaces directly. `security.yml`'s gitleaks scan is a backstop against agent-introduced leaks. `dev-agent`'s broad tool grant has no enforced deny-list beyond prose scope (same gap as Capability above).
- **Observability**: no agent-run logging, tracing, or cost tracking exists beyond the PR comment itself, despite `CLAUDE.md` citing a specific per-PR cost figure (~$0.004) that isn't actually measured or verified anywhere.

## Open gaps (not fixed — flagged for separate prioritization)

1. ~~**Branch protection isn't codified.**~~ **Fixed (2026-07-26)**: `gh api` confirmed `main` had **zero** protection despite `CLAUDE.md` documenting it as fully configured — this audit's original "cannot be verified" framing undersold it; it wasn't unverifiable, it was simply not there. Applied via `PUT /repos/.../branches/main/protection`: 4 required status checks (`Frontend Quality`, `Backend Quality`, `Playwright E2E`, `Secret Scan`, strict mode), 1 required approval with stale-review dismissal, force-pushes/deletions blocked. `enforce_admins` left `false` (repo owner can still bypass as solo maintainer). Merge queue is not settable via this API — still needs manual setup in Settings → Branches → Edit → Merge queue. Still not codified as a file in-repo (drift is possible again without a ruleset committed to source), so treat this fix as a live-setting patch, not a permanent guarantee.
2. **No eval/rubric for agent-generated output.** Neither `agent-review.yml`'s comments nor `dev-agent`'s changes are scored against any standard. **Decision (2026-07-26)**: intentionally deferred, not fixed — at current solo-maintainer PR volume there's no one to act on a scoring signal yet. Revisit once PR/agent-usage volume justifies the overhead.
3. **No technical sandboxing for `dev-agent`.** Its scope ("this repo only") is enforced by instruction text alone. **Partially addressed (2026-07-26)**: trimmed the tool grant in `.github/agents/dev-agent.agent.md` — removed `azure-mcp/*`, `ms-azuretools.vscode-azure-github-copilot/*`, `ms-windows-ai-studio.windows-ai-studio/*`, and mermaid-chart/workspace-management tools, none of which relate to this Next.js/FastAPI/Firebase repo (confirmed via grep — zero real Azure usage anywhere, same template-contamination source as the earlier Avanade branding found in `copilot-instructions.md`). Real process/OS-level sandboxing (container isolation, filesystem scoping) is still open — that's a VS Code Copilot runtime setting, not something fixable from a repo file.
